AirDB.jl

A PostgreSQL-backed persistence layer built on Air.jl's software transactional memory.

AirDB lets you keep shared application state in memory as ordinary Julia objects and have every committed change written to PostgreSQL automatically, in transaction order, without locks in your own code. It is aimed at asynchronous, multithreaded servers whose threads share data and whose write order matters.

using AirDB
using Air                  # for @tx / tx

cfg = DatabaseConfig(; host = "localhost", dbname = "airdb", user = "airdb")
db = create_database(cfg; overwrite = true)

widget = VolatileForm(db, "widget", n = 1)   # a form, persisted on commit
@tx widget[:n] = 42                          # change it inside a transaction
AirDB.sync(db)                               # wait until the writer has saved it
value(widget[:n])                            # 42

The pieces:

  • Form — an immutable, JSON-able nested value. A form is a FormScalar (a bare leaf), a FormContainer (a sequence and a map), a VolatileForm, or a FormExtern (a host-level value that is not JSON itself).
  • VolatileForm — a Form with a stable UUID that persists itself when the transaction that changed it commits, loaded lazily and cached by id.
  • AbstractAirExtern — a host-level value a form can hold (a promise, a socket, a config handle), stored through serialize_extern/deserialize_extern and registered with register_extern.
  • Database — the connection, the single writer actor, the read pool, and the cache. create_database makes a new one; open_database opens an existing one; MemoryDatabase is a fake, in-memory one for tests.
