API Reference

Every public name in AirDB, with its docstring.

AirDB.FormLeaf — Type
FormLeaf

The scalar values a form can hold: String, Symbol, Bool, Int64, Float64, ComplexF64 and Nothing. A FormScalar wraps one; a FormContainer holds forms and leaves.

AirDB.FormNode — Type
FormNode

The concrete kinds of form, as a Union. The operations that produce a form are typed to return this union rather than the abstract Form, so the compiler keeps a scalar form inline instead of boxing it on every read.

source
AirDB.FormValue — Type
FormValue

What a FormContainer holds directly: a Form or a FormLeaf.

source
AirDB.AbstractAirExtern — Type
AbstractAirExtern

The supertype of a host-level value a form can hold without being JSON itself — a promise, a socket, a configuration handle, a cached value. A form stores one inside a FormExtern, which serializes it through serialize_extern and deserialize_extern; the type must be registered with register_extern before a form holding it can be written or read.

source
AirDB.Database — Type
Database

A configured connection to a PostgreSQL database, plus the machinery AirDB keeps around it: a pool of read connections, a weak cache of live VolatileForms, and a single writer actor that persists committed updates in global commit order.

Create one with create_database (to initialize a new database) or open_database (to open an existing one).

source
AirDB.DatabaseConfig — Type
DatabaseConfig(; dbname, user, host="localhost", port=5432, password=nothing,
                 sslmode="prefer", connect_timeout=10, readpoolsize=8,
                 max_batch=1, failure=:abort, retries=nothing, retry_time=nothing,
                 retry_delay=0.1, retry_delay_max=5.0, on_error=nothing,
                 conninfo=nothing)
DatabaseConfig(url::AbstractString; kwargs...)

The parameters AirDB uses to reach a PostgreSQL database and to decide how it behaves. The server is the user's to configure and manage; AirDB only connects.

dbname and user are required unless conninfo is given. conninfo, when set, is a libpq connection string or URI used verbatim (as built by the url method), and the structured fields are ignored.

  • readpoolsize — how many read connections to keep in the pool.
  • max_batch — how many committed updates the writer actor accumulates before flushing. 1 (the default) writes every commit as soon as it arrives.
  • failure — what to do when a database operation fails:
    • :abort (the default) — the writer actor is poisoned and every database operation raises.
    • :retry — the failing operation is retried, reconnecting first, while the retry budget lasts. Reads block until a retry succeeds or the budget is exhausted; writes accumulate in the writer's queue meanwhile.
  • retries / retry_time — the retry budget: at most this many attempts, or at most this many seconds. If both are given, whichever runs out first wins; if neither is given under :retry, a small default is used.
  • retry_delay / retry_delay_max — the delay before the first retry and its ceiling; the delay doubles after each failed attempt up to the ceiling.
  • on_error — a hook on_error(db, err) called on every database error, before the policy is applied. It may return :retry or :abort to override the policy, an Integer to retry at most that many more times, a Real to retry for that many seconds, or nothing to use the configured policy. It can read pending_writes on db to see the unsaved updates.

AirDB.DatabaseError — Type
DatabaseError(cause, failed_writes)

Raised, or recorded on a Database, when a database operation fails under the :abort policy. cause is the underlying exception and failed_writes holds the updates that could not be saved.

AirDB.ExternError — Type
ExternError

Raised when an extern cannot be written or read: its type is not registered, or a form names an extern type the process has not registered.

source
AirDB.ExternTombstone — Type
ExternTombstone

Raised when a form is read back and its extern was written as a tombstone — the symbol :abandoned (an active primitive, like an unresolved promise, that could not be persisted) or :expired. The name is the extern's registered type and kind is the tombstone symbol.

AirDB.Form — Type
Form

The abstract supertype of every form: FormScalar (a bare leaf), FormContainer (a sequence and a map), and VolatileForm (a form that persists itself). The concrete kinds are gathered in FormNode.

Form(x::FormLeaf) -> FormScalar
Form(seq, map) -> FormContainer
form(seqargs...; mapargs...) -> FormContainer

Form(x) for a leaf builds a scalar form, and Form(seq, map) builds a container from collections. form(...) is the general builder: its positional arguments become the sequence and its keyword arguments the map, each converted the way to_form does.

AirDB.FormActorState — Type
FormActorState

The value held by a database's writer Actor. It owns the writer connection, the queues of updates and name registrations not yet written, and the running transaction id. Holding the queues here (rather than writing immediately) is what lets a later policy batch several commits into one database transaction; the strong references in pending keep those forms alive until they are written.

source
AirDB.FormContainer — Type
FormContainer(seq, map)

A form holding a sequence of positional values (seq) and a map of symbol-keyed values (map), each a FormValue. Build one with form, to_form, or from prepared collections.

source
AirDB.FormExtern — Type
FormExtern(value)

A form holding a host-level AbstractAirExtern: a value that cannot be written as JSON directly and is therefore stored through a provider's serialize_extern/deserialize_extern. Build one with to_form or FormExtern(x); use value to get the wrapped object back.

source
AirDB.FormNotFound — Type
FormNotFound(id)

Raised when a form's id is not present in the database.

source
AirDB.FormScalar — Type
FormScalar(value)

A form holding just a leaf: a String, Symbol, Bool, Int64, Float64, ComplexF64 or Nothing. Form(x) for a leaf x builds one, and indexing a container wraps a leaf into one, so every value read out of a form is a form. Use value to get the leaf back.

AirDB.MemoryDatabase — Method
MemoryDatabase() -> MemoryDatabase

A fake, in-memory Database for testing without PostgreSQL. It behaves like a real database — forms persist across commits, named forms work, sync blocks — but keeps everything in memory, saves nothing, and keeps no history.

source
AirDB.VolatileForm — Type
VolatileForm

A Form that is stored in a PostgreSQL database and kept in sync with it. A VolatileForm is a thin wrapper around an Air Volatile{Form}: it can be read at any time, but it may only be written inside an Air transaction (@tx/tx), and when that transaction commits the new value is sent to the database's writer actor.

Every VolatileForm has a stable UUID, and forms may embed other volatile forms (written "@<uuid>" in JSON). Volatile forms are cached per Database by id, so the same form is always the same object within one process.

Create one with VolatileForm(db, args...; kwargs...) or VolatileForm(db, form::Form); retrieve an existing one with get_form.

source

VolatileForm(db::AbstractDatabase, form::Form) -> VolatileForm
VolatileForm(db::AbstractDatabase, args...; kwargs...) -> VolatileForm

Creates a new volatile form with a fresh UUID and registers it with db so it will be written to the database. The arguments of the second form are the same as Form's.

Air.setindex — Method
setindex(f, v, idxs...) -> FormContainer

A copy of f with the value at the path idxs... replaced by v. Purely functional: no VolatileForm is written. A volatile on the update path is eliminated (replaced by its plain value), so the result never contains a volatile whose content the update would have changed; volatiles off the path are kept as links.

A vector key (or :) fans out and builds a new form over the selection.

An integer index equal to one past the end of a sequence appends.

create_database(config::DatabaseConfig; overwrite::Bool=false) -> Database

Initializes a new AirDB database in the PostgreSQL instance described by config — creating the form_history, form_current, and airdb_meta tables and starting a Database for it. The server itself is the user's to provide and manage.

deep_map(fn, f) -> FormNode

fn applied to every node of the tree, bottom-up (a post-order walk): each child is transformed first, then fn is applied to the rebuilt parent. A VolatileForm is passed to fn as the object.

AirDB.deserialize_extern — Method
deserialize_extern(::Val{name}, payload) -> AbstractAirExtern

Rebuild the extern registered under name from the payload the reader parsed. A provider defines a method for each name it registers, dispatching on the Val that carries the name:

deserialize_extern(::Val{:promise}, payload) = Promise(payload)

The payload is ordinary Julia data — a leaf, a Vector, a Dict — because an extern is not required to serialize as a form. The default raises.

AirDB.from_JSON — Method
from_JSON(s::AbstractString) -> Form
from_JSON(resolve::Function, s::AbstractString) -> Form
from_JSON(db::Database, s::AbstractString) -> Form

Reads a Form from the JSON that to_JSON writes. A container is a list [seq, map, held] — a two-element [seq, map] is accepted too, with held false; a bare object is accepted as a form with only a map, and a bare scalar as a scalar form, since both are convenient ways to write one by hand.

A form may link to a VolatileForm, written "@<uuid>". Resolving such a link requires a database, so either pass one, or pass a function that turns a UUID into the value the link should yield. Reading a form that contains a link without a resolver is an error.

A list beginning with the tag extern is a FormExtern: its type is looked up in the registry (see register_extern) and rebuilt with deserialize_extern. An unregistered type is an ExternError, and a tombstone payload (:abandoned or :expired) is an ExternTombstone.

source
AirDB.from_JSON — Method
from_JSON(db::AbstractDatabase, s::AbstractString) -> Form

Reads a form from JSON, resolving any "@<uuid>" links to the (possibly not yet loaded) VolatileForms cached by db.

source
AirDB.get_form — Method
get_form(db::AbstractDatabase, id::UUID) -> VolatileForm

The volatile form with the given id. If it is already cached it is returned immediately; otherwise an unloaded form is created (its body is read from the database on first access). The same id always yields the same object within a Database.

AirDB.hold — Method
hold(f) -> Form
unhold(f) -> Form
isheld(f) -> Bool

hold(f) marks a form as held. A container gets held = true — a copy when it was not already held, f itself when it was — a symbol scalar form gets a leading colon on its name unless it already has one, and any other form (a non-symbol scalar, a volatile) is returned unchanged. unhold undoes it, and isheld tests it.

The flag is part of a form's value: a held form is not equal to an unheld one, the two hash differently, and it is written in the form's JSON, so a held form round-trips through the database.

Examples

hold(form(a = 1))          # the same form, now held
hold(Form(:abc))           # Form(:abc) with a leading colon: Form(Symbol(":abc"))
hold(Form(Symbol(":abc"))) # unchanged — colons do not stack
source
AirDB.isheld — Method
isheld(f) -> Bool

Whether f is held — a container with held = true, or a symbol scalar form whose name starts with a colon. Any other form is not held. See hold.

AirDB.named_form — Method
named_form(db::Database, name; create = false, value = nothing)

Look up the form registered under name, which may be a Symbol or a String. create controls what happens when the name is not found:

  • create = false (the default) — raise if no form is registered under name;
  • create = true — create a new named form and return it, raising if the name is already in use;
  • create = nothing — never raise; return nothing when the name is not found.

value is the new form's initial value, used only when a form is created. It is converted with to_form, so a Form is used as-is, a number becomes a FormScalar, a collection becomes a container, and leaving it out gives an empty container; or it may be an existing VolatileForm, in which case no new form is made and the name is pointed at the given one.

Creating is transactional: it joins the caller's transaction if there is one, and otherwise runs in a transaction of its own.

Examples

root = named_form(db, "root"; create = true, value = form(version = 1))
named_form(db, "root")                 # the same form
named_form(db, :root)                  # Symbol and String agree
named_form(db, "root"; create = true)  # ERROR: already in use
named_form(db, "other"; create = nothing)   # nothing

AirDB.pending_writes — Method
pending_writes(db::Database)

The updates the writer has not yet saved. This is meant for use inside an on_error hook, where the writer is between attempts and its queue is the work that a successful retry would save. If the writer has already failed, the writes from the failed batch are returned instead.

source
AirDB.register_extern — Method
register_extern(name::Symbol, ::Type{T}; isequal, hash) -> ExternRegistration

Register the extern type T under name, so that forms holding it can be written and read. name is what appears in the stored JSON — register_extern(:promise, Promise) writes ["extern", ":promise", …] — and is looked up again on read.

isequal and hash are the equality and hash used for FormExterns wrapping a T, and they must agree with one another (equal externs hash equal). Both default to identity of the object, which is the safe choice for a live handle; supply them to compare by value instead:

register_extern(:config, Config;
                isequal = (a, b) -> a.version == b.version,
                hash = (x, h) -> hash(x.version, h))

Registering the same name and type twice is a no-op; registering a name already taken by a different type is an error.

The registry lives in memory, so a package that provides an extern type should register it from its __init__, which runs when the package is loaded — a top-level call would run at precompilation and be lost.

AirDB.serialize_extern — Method
serialize_extern(obj::AbstractAirExtern) -> payload

The JSON-able payload that stands for obj in the database: a leaf, a Vector, a Dict, or a Form. A provider defines a method for each extern type it owns — importing the function first, since it is AirDB's:

import AirDB: serialize_extern
serialize_extern(x::MyExtern) = …

The default raises, so an extern type that never implemented serialization fails loudly rather than being stored as a hole.

serialize_extern runs on the database's writer thread, while the committed form is encoded, so it must not block. An extern that stands for something that may not be ready should return a tombstone (see ExternTombstone) rather than wait for it:

serialize_extern(p::Promise) = isready(p) ? fetch(p) : :abandoned

AirDB.status — Method
status(db::Database) -> (npending, error)

The number of updates queued for the writer but not yet written, and the last error the writer saw (or nothing). If the writer actor is poisoned, the error is returned as the second element.

AirDB.sync — Method
sync(db::Database)

Blocks until every update sent to db before this call has been written to the database. The writer actor is sequential, so once it has processed the sync message every earlier write is durable.

Raises the recorded DatabaseError if the flush failed.

source
AirDB.to_JSON — Method
to_JSON(f::Form) -> String

The form as a JSON string. A container is written as the three-element list [seq, map, held], so the format is self-describing: from_JSON reads a list as a container and nothing else. A scalar form is written as its bare leaf.

A String and a Symbol are both written as JSON strings, with the first character inside the quotes saying which: ' for a string and : for a symbol. A Float64 is a plain number, always with a decimal point or an exponent so that it reads back as a float rather than as an integer. A complex number has no JSON equivalent and is written as {"re": …, "im": …}, always, even when its imaginary part is zero. A VolatileForm is written as the string "@<uuid>"; it is never expanded, so cyclic links are safe to write. A FormExtern is written as the tagged list ["extern", ":<type>", <payload>], where the payload is whatever serialize_extern returns.

Base.getindex — Method
f[idxs...] -> Form

Index into a form along a path of keys. An Integer is a sequence position, a Symbol a map key, and a VolatileForm met along the way is transparent (its value is used). The value at the final key is returned as a form — a leaf comes back as a FormScalar (use value to get the leaf), and a final VolatileForm is returned rather than expanded.

A vector key (or :, meaning every sequence position and map key) fans out: the result is a new FormContainer with one entry per key, built by the outer product of the vector keys, with volatiles eliminated. Missing keys raise.

Examples

f = form(10, meta = form(n = 1))
f[1]              # Form(10)
value(f[1])       # 10
f[:meta, :n]      # Form(1)

Base.map — Method
map(fn, f) -> Form

A form with the same keys as f (both its sequence and its map), every immediate value replaced by fn(value). fn receives a VolatileForm value as the VolatileForm object, so it decides whether to keep or drop it. The results are converted the way any form value is.

If f is a VolatileForm, the function is applied to its value; if f is a FormScalar, it is applied to the leaf.

source
Base.setindex! — Method
setindex!(f, v, idxs...) -> v

Walks the path idxs... and sets the value of the deepest VolatileForm on it — the last volatile among the values along the path, including the final one. The volatile is rebuilt along the keys below it. If no value on the path is a volatile, the call raises, because a persistent Form cannot be mutated.

Because it writes a volatile, this must run inside an Air transaction (@tx/tx); the outer volatiles are read (and registered with the transaction), and only the target is written.

An integer index equal to one past the end of a sequence appends.

Examples

a = VolatileForm(db, n = 0)
@tx a[:n] = 5            # writes the volatile a
@tx a[:deep, :n] = 1     # writes the deepest volatile on the path
