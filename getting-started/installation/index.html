Installation¶

AirDB depends on Air.jl 0.3 and LibPQ.jl. Add it to a project with:

using Pkg
Pkg.add("AirDB")

If AirDB is not in your registry yet, add it from its repository instead:

Pkg.add(url = "https://github.com/noahbenson/AirDB.jl")

You will also use Air directly for the transaction macros and types:

using AirDB
using Air

A PostgreSQL server¶

AirDB never creates or manages a PostgreSQL server — it connects to one you provide. For experimenting, the repository ships a docker-compose.yml that starts a throwaway server:

docker compose up -d        # postgres:16 on localhost:5432, user/db "airdb"

The examples in this book use the database name airdb_test, the user airdb, and the password airdb; adjust them for your server.

Configuring a connection¶

Everything AirDB needs to reach the server goes in a DatabaseConfig. The structured fields cover the common case; you can also hand it a libpq URI or connection string, which is used verbatim.

cfg = DatabaseConfig(;
    host     = "localhost",
    port     = 5432,
    dbname   = "airdb_test",
    user     = "airdb",
    password = "airdb",
)
# ... or a libpq URL / connection string:
cfg = DatabaseConfig("postgresql://airdb:airdb@localhost:5432/airdb_test")
cfg = DatabaseConfig("host=localhost port=5432 dbname=airdb_test user=airdb")

The remaining fields tune the read pool, write batching, encoder tasks, and failure behavior. They are explained where they matter:

cfg = DatabaseConfig(;
    dbname        = "airdb_test",
    user          = "airdb",
    readpoolsize  = 16,     # connections kept for reads
    max_batch     = 1,      # commits accumulated before one database write
    failure       = :isolate, # :abort or :retry; see Failures
    encoder_tasks = 4,      # tasks that encode committed batches
    max_pending   = 256,    # committed-but-unwritten batches allowed
)

See Commits and durability for batching, Concurrency for the encoder tasks and the pending bound, and Failure policies for the failure setting.
