Failures

Unreviewed content

This page was written with AI assistance and has not been reviewed by a human. It may contain errors, omissions, or outdated information.

The records a quarantined batch leaves behind, the queries that inspect them, and the calls that clear or retry one. See Inspecting failures.

FailedItem¶

FailedItem

One object that a quarantined batch could not save: its kind (:form, :actor, :promise, :stream, :extern, or :name), its id (a UUID, a (type, id) pair, or a name), the live object when one is known, and the pending write that failed.

FailureRecord¶

FailureRecord

One quarantined batch: the batch’s sequence number, the database error, when it happened, and the FailedItems it contained.

ReadFailure¶

ReadFailure

A read that failed and was not retried successfully: the error, when it happened, the operation (:load, :metadata, :name, :read, ...), and the object id when the read was for one.

FailedObjectError¶

FailedObjectError(id, record)

Raised when an object whose database write was quarantined is loaded. The live in-memory object remains readable; reloading it would silently return the older row, so it raises instead. See write_failures and clear_write_failure!.

write_failures¶

write_failures(db) -> Vector{FailureRecord}
write_failures(db, id) -> Vector{FailureRecord}

The quarantined write batches, oldest first, or those touching id (a UUID, an extern (type, id) pair, a name, or an explicit (kind, id) key).

failed¶

failed(db, id) -> Bool

Whether id currently has an unsaved (quarantined) write. A live in-memory object is still readable; loading it raises FailedObjectError.

clear_write_failure!¶

clear_write_failure!(db, id; retry = false) -> Bool

Acknowledge and remove the quarantined writes for id. With retry = true, also re-stage the object’s current in-memory value for another write (a form’s value and metadata, an actor’s value, a stream’s snapshot, an extern’s bytes, the current name mapping, or a promise’s outcome). Returns whether anything was cleared.

clear_write_failures!¶

clear_write_failures!(db) -> Nothing

Acknowledge and remove every quarantined write.

read_failures¶

read_failures(db) -> Vector{ReadFailure}
read_failures(db, id) -> Vector{ReadFailure}

Reads that failed, oldest first. They do not block later reads; clear them with clear_read_failures!.

clear_read_failures!¶

clear_read_failures!(db) -> Nothing

Clear the read-failure history.

pending_writes¶

pending_writes(db::Database)

The updates the writer has not yet saved — form writes, actor values, queued stream snapshots, resource bytes, promise rows and settlements, names, and metadata-only edits — plus any writes that were quarantined by the failure policy. This is meant for use inside an on_error hook, where the writer is between attempts and its queue is the work that a successful retry would save. If the writer has already been poisoned (:abort), the writes from the failed batch are returned instead.
