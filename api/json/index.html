The textual form used for storage and interchange. See The JSON format.

to_JSON¶

to_JSON(f::Form) -> String

The form as a JSON string. A container is written as the two-element list [seq, map], so the format is self-describing: from_JSON reads a list as a container (or an extern — see below). A scalar form is written as its bare leaf.

A String and a Symbol are both written as JSON strings, with the first character inside the quotes saying which: ' for a string and : for a symbol. A Float64 is a plain number, always with a decimal point or an exponent so that it reads back as a float rather than as an integer. Values outside JSON’s number model are marked strings: a non-finite Float64 — Inf, -Inf, or NaN — is "#inf", "#-inf", or "#nan", a BigInt is "#big:<digits>", a Rational is "#rat:<num>/<den>" or "#bigrat:<num>/<den>", and a BigFloat is "#bigfloat:<precision>:<digits>" (with its precision in bits). The # marker cannot be confused with a string ('), a symbol (:), or a link (@). A complex number has no JSON equivalent and is written as {"re": …, "im": …}, always, even when its imaginary part is zero; a Complex{BigFloat} writes its parts as BigFloats. A VolatileForm is written as the string "@<uuid>"; it is never expanded, so cyclic links are safe to write. A FormExtern is written as the object {"extern": "<type>", "id": "<id>"} — or {"extern": "<type>"} when it is dead — and its bytes live in the resources table. An ActorForm, PromiseForm, and StreamForm are written as the links "!<uuid>", "~<uuid>", and "&<uuid>"; a promise is a link whether it is pending, delivered, or failed.

to_JSON(vf::VolatileForm) -> String

The volatile form’s link text, "@<uuid>" (without the surrounding JSON quotes).

from_JSON¶

from_JSON(s::AbstractString) -> Form
from_JSON(resolve::Function, s::AbstractString) -> Form
from_JSON(db::Database, s::AbstractString) -> Form

Reads a Form from the JSON that to_JSON writes. A container is a list [seq, map]; a bare object is accepted as a form with only a map, and a bare scalar as a scalar form, since both are convenient ways to write one by hand.

A form may link to a VolatileForm, written "@<uuid>". Resolving such a link requires a database, so either pass one, or pass a function that turns a UUID into the value the link should yield. Reading a form that contains a link without a resolver is an error.

An object with the plain key extern is a FormExtern: its type is looked up in the registry (see register_extern) and its bytes are read from the resources table lazily. An object with no id is a dead extern; an unregistered type is an ExternError.

from_JSON(db::AbstractDatabase, s::AbstractString) -> Form

Reads a form from JSON, resolving any "@<uuid>" links to the (possibly not yet loaded) VolatileForms cached by db, and any extern references through db’s resource registry.
